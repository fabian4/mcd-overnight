# 麦当劳过夜

帮用户回答：从这里出发，哪家麦当劳能营业到我需要的时间，怎么过去？优先给一个可行选择，再给至多两个备选。

## 输入与时间

- 确认城市、出发地点及需要等待的时段。已有信息直接使用；缺少城市或地点、且存在同名地点时，先问清楚，不默认上海，也不擅自读取定位。
- 用户说“现在”，使用 `now-time-info`；工具不可用时使用已知系统时间并说明来源。中国门店按 Asia/Shanghai 判断。
- “凌晨两点到”是预计抵达时间，不是当前时间。“等到早晨”若未说明离开时间，可按早上 06:00 初筛并明示假设。
- 已知目的为通宵时，优先查询 24h 店；只有需要比较非 24h 备选时才补问具体等待时段。

## 数据来源与调用

有已配置的麦当劳 MCP 工具时，先实时查询，再用快照补充；不要让用户把 Token 发在聊天里。端点为 `https://mcp.mcd.cn`，Streamable HTTP，认证仅从环境变量 `MCD_MCP_TOKEN` 获取，不打印、记录或写入文件。

只允许调用以下只读工具，参数以实际工具 schema 为准：

- `now-time-info`：确认当前时间。
- `query-nearby-stores`：用 `beType=1`、`searchType=2`、`city`、`keyword` 查询用户指定的地点。优先精确的站名、航站楼或路名。

先查用户地点；结果不足时最多再查两个与该地点有关的关键词，串行调用、间隔至少 1 秒。按 `storeCode` 去重，保留每条结果的查询关键词和距离；不要跨关键词直接比较距离。不得为了补齐结果做全城遍历。

没有可用 MCP、未配置凭据或查询失败时，读取本仓库根目录下的 `data/overnight-stores.json`；相对本 Skill 文件路径为 `../../data/overnight-stores.json`。需要城市概览时再读 `../../data/ranking.json`。仅复制 Skill 文件夹安装时，这些数据可能不存在：明确说明缺少快照，请用户配置 MCP 或提供仓库位置，不编造结果。

快照字段为 `storeCode`、`storeName`、`city`、`address`、`start`、`end`、`businessStatus`、`is24h`、`lateNight`、`hubKw`、`distance`。实时营业时间字段为 `businessStartTime`、`businessEndTime`，先归一化为 `start`、`end`。

- 当前快照采样日期：2026-10-14。快照中的 `businessStatus` 只代表采样时状态，不能声称现在营业。
- 实时工具错误、认证失败、响应格式无法解析，与成功返回空列表分开说明；不要把错误说成“附近没有店”。
- 单次最多返回约 5 家，成功空列表也只表示本次未查到，不表示区域内绝无门店。
- 同一门店有实时结果时，以实时字段为准；实时标记暂停的店不可用快照覆盖成营业中。

## 推荐判定

1. 排除实时 `businessStatus=false` 的门店。状态缺失则写“当前状态未确认”，不能默认为营业。
2. `start=00:00` 且 `end=23:59` 视为标注 24h；它不保证未来不会临时闭店。
3. 非 24h 店按完整营业区间判断能否覆盖抵达至离开的整个时段。跨午夜需按日期展开；例如 09:00–02:00 在次日 01:00 营业，02:00 已关门，不能支持等到 06:00。`lateNight=true` 仅用于筛选，不能替代时段判断。
4. 起止时间缺失、格式异常或相同且未明确标注 24h 时，营业时段视为未知。实时 `businessStatus=true` 只代表现在，不能证明预计抵达时仍营业。
5. 同一查询地点内，优先时段覆盖且实时确认营业的 24h 店，再按接口距离排序。距离未知的候选不要声称“最近”。非 24h 店只作为可覆盖所需时段的备选；提前关门的店单独标明“只能临时等候”。
6. 注意地址中的安检内、国际出发、航站楼等限制；不能假设用户能进入。能否通行未知时明确指出，优先可到达的安检外候选。

## 距离、价格与导航

- 接口 `distance` 是相对该次查询关键词的距离，不能当成用户 GPS 距离、步行路线或步行耗时。
- 快照距离只有在 `hubKw` 与用户地点相符时才能引用，写“距××约 650 米（采样接口距离）”；其他枢纽门店只能作为异地备选，不沿用该距离。是否为 1.5 km 内候选也必须基于匹配地点的距离。
- MCP 经纬度为 0.0，不可用于导航。页面近似坐标、道路中心点也不可用于精确测距或路线判断。
- 不根据机场、车站、店名或地址推断价格档位、有无优惠；忽略快照遗留的 `tier` 字段。用户另问价格时，说明本 Skill 不核验当前菜单价格。
- 用完整店名和地址生成高德搜索链接，参数必须 URL 编码：`https://uri.amap.com/search?keyword=<店名和完整地址>&city=<城市>&view=map&src=mcd-overnight&callnative=1`。不传估算坐标。若用户指定 Apple Maps，可用 `https://maps.apple.com/?q=<城市、店名和完整地址>`。

## 输出

先给结论和首选，包含店名、完整地址、24h 或营业区间、距离所参照的地点，以及导航链接。24h 店写“24 小时营业”；非 24h 店必须显示完整起止时间，例如“07:00–23:00”，跨午夜写“09:00–次日 02:00”，不要只写“23:00 关门”。起止时间不全时写“营业时段待确认”，不补造时间。需要时给至多两个备选；不要默认展开城市排行榜。

区分“本次实时查询（北京时间和日期）”与“2026-10-14 采样、未实时核验”。未来抵达的推荐说明依据为公布营业时段，当前状态仅作参考。

没有合适结果时，说明是未查到、时段不覆盖、暂停营业还是查询失败。可提供相关地点的一次补查或明确标识的快照候选；不要把同城远处店说成附近，也不要仅凭样本宣布整座城市没有通宵店。

末尾保留一句：**24 小时营业不代表允许留宿，以门店现场规则为准；请安静消费、不占多座。** 不堆叠重复提示。

## 边界

不调用订单、优惠券、抽奖、地址管理或其他修改账户的工具。不承诺座位、插座、厕所、行李寄存、安全保障或可留宿；接口没有库存、售罄、客流和排队数据，也不据此推断。
